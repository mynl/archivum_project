Introduction

Archivum is a personal document and reference management system designed for high-performance indexing and retrieval of academic papers, books, and technical documents.

Unlike traditional managers, Archivum prioritizes identity over location. Documents are tracked by their cryptographic content hash, ensuring that your library remains intact even if files are moved, renamed, or synced across different devices.

Architecture

The library is built on a three-tier database structure stored as high-performance .feather files:

Ref

Bibliographic Metadata
Tags, authors, titles, journals, and years. Synchronized with an external BibTeX file.

Doc

Physical Files
Path, size, creation date, and content hash. Managed in a sharded directory structure.

Ref-Doc

Junction Table
The bridge that links high-level tags to physical content hashes.

Read

Read History
Tracks timestamps, view counts, and origin URLs (referrers) for every document opened.

Semantic Cache

Embedding Cache
Stores high-dimensional vectors for papers, enabling instant re-analysis and galaxy mapping without re-encoding.

Full-Text Extraction

When documents are imported, Archivum automatically extracts their text content. This text is sharded into a separate directory, enabling blazing-fast full-text searches across thousands of documents using the integrated Ripgrep engine.

/view/<tag> opens the tag's primary document. A PDF opens in Archivum's own reader: a browser tab titled TAG | title, showing one page at a time at Page Fit (PgDn and the arrows page at once; the mouse wheel turns pages while the page fits, and scrolls within the page when zoomed in), with the PDF.js toolbar for find, outline, thumbnails, print, and download; it reopens a document at the page you left. Other formats (DjVu, EPUB, and so on) go to the browser as before. /view-hash/<hash> does the same by hash. Each opening counts as one read. /file/<tag> and /file-hash/<hash> serve the raw bytes (the reader fetches through them, in chunks) and do not count as reads. /text/<tag> serves the extracted text for the primary document as plain UTF-8, and returns 404 if no text has been extracted (non-PDF formats, or a document imported before extraction); it counts as a read.

Query Syntax

The primary search bar on the Query page is powered by querexfuzz. A small live status line below the input shows the exact expression that will be run.

1. Live Query Interpretation

For quick lookups, plain text becomes a fuzzy # search. Explicit querexfuzz syntax is limited to the 50 most recently added matches by default.

Syntax Description
keyword Runs as # keyword for fast fuzzy matching.
!AuthorName Runs as recent top 50 !AuthorName.
field ~ pattern Runs as recent top 50 field ~ pattern.
year > 2020 Runs as recent top 50 year > 2020.
q top 20 recent Runs exactly as top 20 recent.

Querex symbols are #, ~, =, <, >, and !. Use q when you do not want automatic recent top 50 wrapping.

2. Full Querexfuzz (Prefix: q)

Prefix your query with q to pass an expression through unchanged.

q select year, author, title author ~ /Wang, R/ and year > 2019 order by -year
  • Fuzzy Search: Use # for fast skimmatch fuzzy matching. q # machine learning
  • Projection: Control which columns are returned using select col1, col2.
  • Sorting: Use order by field or order by -field for descending.
  • Limits: Add top 50 to restrict result size.
  • Library fields: added is when the reference entered the library, and is what recent sorts by; create is when its primary document's file was created. docs counts the documents linked to the reference: where docs == 0 finds references with no document, where docs > 1 those with alternates.
  • Citation counts: cites is the latest count collected on the Audit page, cites_asof its date, and cites_1y the growth over the last year (empty until a count is a year old). q !wang where cites > 100 finds Wang's works cited more than 100 times, and q where cites > 0 order by -cites lists the most cited first. A reference with no count matches no comparison, so it is left out. New counts are picked up on the next search. The counts are not part of the references and never appear in the BibTeX.

For the complete grammar, visit the Querexfuzz Project.

BibTeX Format

Archivum stores bibliographic metadata in a deliberately narrow BibTeX-compatible shape. Keeping entry types and fields normalized makes imports safer, keeps Feather tables predictable, and reduces BibTeX synchronization noise.

Entry Types

Use one of these types for new or edited records:

article, book, techreport, misc, incollection, unpublished, inproceedings, phdthesis
Supported Fields

Restrict BibTeX fields to the following set unless a specific import requires a temporary exception:

tag, type, title, year, author, journal, volume, number, month, pages, booktitle, editor, edition, doi, isbn, publisher, institution, address, url, archivePrefix, arxivId, eprint
Conventions
  • Tag: The BibTeX key is the Archivum tag. Keep it stable after import because links, citations, reports, and document mappings use it as the reference identity.
  • Type: Store the entry type without the leading @ in editable metadata, for example article rather than @article.
  • Authors and editors: Use BibTeX and between names. Prefer canonical names that match the library's author normalization.
  • Dates: Keep year as a four-digit year when known. Use month only when it is bibliographically meaningful.
  • Identifiers: Prefer DOI, ISBN, URL, and arXiv fields over embedding identifiers in titles or notes.
  • Document paths: Do not add Mendeley-style file fields manually; Archivum maintains document links through the ref-doc table and importer workflow.
@article{Wang2024,
  author = {Wang, Ruodu and Smith, Jane},
  title = {Spectral Risk Measures},
  year = {2024},
  journal = {Insurance Mathematics and Economics},
  doi = {10.0000/example}
}

Query Page

The default landing page for searching your library.

  • Search Bar: Results appear instantly as you type, and the live status line shows the interpreted querexfuzz expression. Up/Down walk your past searches, newest first, and run the one shown. A search is remembered once you stop: 10 seconds without a new search, clearing the box, or pressing Up. A burst of typing leaves one entry, its final text. The server keeps the history in the library folder (search-history.csv), so every browser and address shares it; read-only bridge visitors neither add to it nor see it.
  • Quick Actions:
    • Recent: The last 50, 100, or 250 references added to the library, newest first. This is the reference's own date added, not its document's: replacing a document does not move a reference up. Reference only, below the divider, lists references with no document.
    • Read: Your reading history, top 50. The main button blends how often and how recently you read: it sorts by read_rank = log2(read count) + (days since a fixed date of the last read) / h, so one doubling of reads is worth h days of recency. With h = 30 (read_half_life_days in the config), a paper read 8 times and last opened 90 days ago ties with one read once today. The dropdown also offers Read by count and Read by recent.
    • Mine: Your own works, newest first: every reference whose author matches owner_author_pattern in the config (a regex). Disabled while that is empty.
    • Random: Discovers papers using a random 2-digit hex hash prefix.
  • View Modes: Toggle between List, Verbose (all metadata), and Table.
  • Tag Links: In every view, a tag links to the reference's primary document. A reference with no document shows its tag muted, with no link; its Edit pencil stays.
  • Citation count: A List entry shows 1,234 cites after the author and source, before the hash, when a count has been collected on the Audit page; hover for the date. A reference with no count shows nothing there.
  • Document Hash: Each List entry ends with the first 8 characters of the document hash, in small upper-case monospace. This is the hash of the reference's primary document — the one View opens — so it lines up with Ripgrep results and with filenames in the document store. It is omitted if a query's explicit select clause drops the hash column. A reference with no document shows a muted no doc instead. After the hash come the reference's date added (YYYY-MM-DD) and its read count (×N, omitted when never read); both are looked up by tag, so they appear whatever the query selected. Table and Verbose views are unchanged.
  • Exports: Download the current result set as CSV, BibTeX, or BibTeX+ from the Export menu. BibTeX+ adds Archivum document hashes and Mendeley-style file fields when a matched document path is available. The file paths point at the real document store (symlinks resolved), not the app-home link.
Network & Discovery

Advanced visualization modes for exploring connections and thematic clusters.

1. Social Graph (Co-Authorship)

Maps the "Social Network" of your library. Nodes represent authors, and edges represent papers they have co-authored.

  • Weighting: Author nodes are sized by the total number of papers they have in the current search universe.
  • Connectivity: Edges connect authors who appear on the same paper. Edge thickness indicates the number of collaborations.
  • Interaction: Click an author to see their papers. Double-click to "Rebase" the graph onto that author.
  • Ripgrep Universe: Searches using rg are case insensitive by default, matching the Ripgrep page behavior. Use Options → Case sensitive rg when exact case matters.
  • Live Interpretation: The status box shows whether the current text is a raw query universe, a q querex universe, an rg full-text universe, or a combined q ... rg ... universe.
  • Search History: Up/Down in the search box recall past Social and Semantic searches, kept by the server as on the Query page. A recalled search runs on Enter or a button, as a typed one does.
2. Semantic Galaxy (Thematic Clustering)

Uses Machine Learning to project your papers into a 2D "Galaxy" where distance represents semantic similarity.

  • Embedding: Papers are converted into high-dimensional vectors (384-D) using the all-MiniLM-L6-v2 transformer model.
  • Cache: Embeddings are cached per library and source, so repeated runs usually reuse existing vectors. First runs, new documents, or longer full-text windows may need to encode missing papers.
  • Projection (UMAP): These vectors are flattened into 2D coordinates using UMAP, preserving local and global structures while using available CPU cores.
  • Clustering (HDBSCAN): HDBSCAN automatically identifies dense "Constellations" of related papers.
  • Lone Stars: Points colored grey represent "Noise"-papers that don't statistically fit into any specific cluster.
  • Sources: Analysis can be run against Title & Metadata, the first 2,000 characters of Full Text, or the first 4,000 characters of Full Text.
  • Verbose Logs: Verbose mode reports timing spans for universe resolution, embedding cache lookup, model load, missing embedding generation, UMAP, clustering, serialization, and browser rendering. When an rg clause is used, it also shows the ripgrep command and cache hit/miss.
Ripgrep (Full-Text)

Search inside the actual text of your PDF collection.

  • Streaming Results: Matches are streamed to the browser in real-time.
  • Search History: Up/Down in the search box recall past searches, kept by the server as on the Query page. A recalled search runs on Enter or a button, as a typed one does.
  • Regex Feedback: The small status line below the input checks whether the typed pattern is valid JavaScript regex syntax before running ripgrep.
  • Context Control: Specify how many lines of context to show before and after matches.
  • Summary Mode: Groups matches by year and author to provide statistical insights into your library's content.
  • Exports: Send the top hash-limited matches to Query, or download all matches as CSV, BibTeX, or BibTeX+ from the Export menu.
Report Studio

A specialized workflow for synthesizing research findings into persistent journals.

  • Integrated View: Research reports are rendered as HTML fragments using Pandoc and embedded directly within the Archivum interface.
  • Archival PDFs: (Admin only) Generate professional-grade PDFs using Quarto + Tectonic with scrartcl styling (A4, 10pt font).
  • Markdown Support: Add introductions and research notes to your reports using standard Markdown syntax.
  • Smart Caching: Rendered HTML, PDF artifacts, and report images are cached in the library's exports/ directory. If a report is viewed or downloaded again, Archivum serves the cached version instantly unless the source .qmd file has been modified.
  • Raw Source: Access the raw .qmd file for manual editing or custom publication workflows.

Ingest (Admin Mode)

Import new documents or BibTeX entries into the library, one at a time or as a queue.

  • Source: Select or drop one or many files, paste a local file path, point at a folder (every document in that folder, not subfolders), or enter a URL (including Arxiv/DOI support). Pasted BibTeX in Zone B applies only when you stage a single document.
  • Formats: PDF, DjVu, EPUB, MOBI, CHM, XPS, FB2. Only PDFs preview inline and have their text extracted; for the others you paste the full BibTeX yourself, since metadata discovery usually finds nothing.
  • Queue: Documents are handled one at a time in the same workbench. The header shows Importing M of N with a progress bar. Remaining documents are analysed on a background thread while you work, so later ones usually open instantly.
  • Workbench: Edit the source BibTeX while viewing the staged document and metadata candidates.
  • Import Preview: The preview runs the real BibTeX importer without saving. It shows the BibTeX that will be produced after author Trie normalization and tag allocation.
  • Tag Allocation: Previewed tags are advisory. The final tag is recomputed when you click GO: Archive Document and is locked down only when the library update is saved.
  • Duplicate Detection: A matching hash is flagged in the header. Any match warns in the preview and nothing is refused: a red warning means the same file is already archived, an amber one the same DOI or title. GO: Archive Document then stops on that document with a banner; Import anyway as <tag> in the warning adds it as a separate reference with its own tag (a same-file import links the new reference to the same file). If the file is new but its DOI or title matches, the warning also offers Replace document on <tag>, or Attach this file to <tag> when that reference has no document, optionally updating its metadata from your BibTeX too.
  • Replacement: Replacing links the new file to the existing reference at priority 0, so View and search results now show it. Any previous document is kept as an ordered alternate — nothing is deleted, and the change can be undone from the CLI with link-tag-hash.
  • Skip / Cancel: Skip abandons the current document and moves to the next. Cancel batch abandons the whole queue. Both only discard staged copies; your original files are never touched.
  • Results: You stay on the Ingest page throughout. Each outcome — imported, replaced, skipped, or failed — is appended as a colored banner below the workbench, and a summary appears when the queue drains.
  • Reference only: Add reference only (no document) in Zone B opens the workbench without a document, carrying any BibTeX pasted there. Preview and GO: Add Reference run the same importer (tag allocation, name normalization, duplicate checks); a DOI or title match gives an amber warning linking the existing reference, and the reference is added only on Import anyway. The new reference heads Recent and appears under Recent › Reference only until a document is attached.
  • Commit: Archive Document reruns the same import path, shards the document into the library store, updates the Feather data, and extracts text for new PDFs. Web ingests deliberately write no audit files; bulk CLI import-bibtex runs still do. Use archivum clean-audit -x to prune old audit and staging scratch.
Editor (Admin Mode)

A high-density interface for bulk metadata management.

  • Tag Sidebar: Live-filterable list of every tag in your library. Up/Down walk the list from the filter box or from anywhere outside a text field; inside the BibTeX box they move the caret.
  • Documents: Below the BibTeX, one row per linked document, primary first: hash, version, name, type, size, file created (the file's own date, distinct from the reference's date added), and reads. View opens it; Make primary makes it the one View and search results use; Unlink removes the link only (the file and its document row stay; if no other reference links it, the confirm says it becomes an orphan, which archivum validate orphans lists). Link existing takes a hash prefix of at least 6 characters that matches exactly one document, with suggestions as you type: for a book and its chapters sharing a file, or to re-link after an unlink. Attach file… opens Ingest for this reference: stage the file and choose Make primary document of <tag>; any current document is kept as an alternate.
  • Delete: Delete <tag>… opens a confirm panel; only the separate Delete <tag> permanently button acts. The reference and its links go and bibtex.bib is rebuilt; documents, document rows, and read history stay. An audit copy (BibTeX plus % added and % link hash version priority lines) is written to the library's edit-audit/ folder; the CLI's delete-tag writes one too.
  • Merge: For two records of one work, open the survivor and choose Merge another reference into <tag>…, then pick the other tag. The preview shows an editable merged entry (the survivor's fields win, the other fills the gaps, the tag cannot change), a table of conflicting fields, and what happens to each document (the survivor's keep their order, the other's are appended, duplicates dropped). Swap roles makes the other one the survivor. The merge saves once, keeps the earlier date added, and writes both originals to edit-audit/.
  • Citations: A deleted or merged-away tag leaves bibtex.bib and its linked copy, so manuscripts that cite it stop resolving. There is no alias mechanism: biblatex's ids field is not honored by pandoc citeproc.
  • Date added: Shown under the title, read-only. It is set when the reference is first saved and kept through edits and tag renames; it never appears in the BibTeX.
  • Unsaved changes: After typing in the BibTeX box, loading another tag asks before discarding the edit. Saving or Cancel clears the question.
  • Direct Edit: Edit the underlying BibTeX source directly and save with Ctrl+S or Save Changes. The editor reloads with the saved entry, and a status line left of the buttons says so (with View when there is a document); it closes itself after 20 seconds. A refused save, such as a tag already taken or BibTeX that does not parse, puts the reason there instead, stays until closed, and keeps your edit in the box. A renamed tag is renamed in the sidebar too, in its old place.
  • Deleting a field: The box is the whole entry: delete a field's line and Save deletes the field; Merge does the same with its merged entry. Values must be in braces, year = {2017}: a field written another way, such as year = 2017 or doi = "…", refuses the save and is named in the status line, rather than being silently dropped. A field the library does not keep (not in ref_columns, such as note or abstract) is dropped from the saved entry, and the status line names it and stays up. Field names ignore case, so DOI is doi.
Audit (Admin Mode)

Checks the DOIs of a chosen set of references and writes a correction only for the rows you tick. Reached from More → Audit. It is separate from Health, which checks files and links.

  • Subset: The box takes the same queries as Network (q author ~ /Wang/ rg risk) and shares its Up/Down history. Enter selects. An empty box is the whole library. A reference with no document is included, unless the query has an rg part.
  • Summary: For the subset: references, with and without a DOI, malformed DOIs, DOIs needing attention, and references sharing a DOI with another (compared without case). All computed from the library.
  • Normalize DOIs: Lists each DOI stored with an https://doi.org/ or dx.doi.org address, a doi: prefix, URL-encoding (%2F), or a trailing ., , or ;, beside the bare 10.… form. Capitals are kept. The proposed value can be edited before it is committed.
  • Show DOIs needing attention: Lists values that are not a DOI even after normalization. There is nothing to commit; the tag opens Edit.
  • Check DOIs…: Tests each DOI in the subset against the sources. OpenAlex is asked first, 100 DOIs a request, which also collects the citation counts. Crossref is then asked about each DOI OpenAlex does not confirm, and doi.org about each DOI neither has. The confirmation gives the requests as a range, since how many DOIs go on is not known until OpenAlex has answered. Nothing is sent until Start run, only DOIs are sent, and a DOI checked in the last 30 days is skipped.
  • Show DOI check results: The DOIs by class, with the library's title, first author and year beside the source's, and the title similarity from 0 to 1. Verified: the title matches (0.9 or more) and the first author agrees. Year differs: verified, but the years are more than one apart. Weak match: the title is only close (0.6 to 0.9). Mismatch: the title is under 0.6 or the first author differs, so the DOI is probably another work's. Unresolved: doi.org has no such DOI. Exists, not compared: the DOI is registered, but neither source has a record (a data set or a DataCite DOI, for instance). Shared: the DOI is on another reference too; duplicates are merged in Edit. The table appears by itself when a check ends.
  • Correcting a checked DOI: Unresolved, mismatch and weak-match rows can be ticked. Type the right DOI in Replacement DOI, or leave it empty to clear the DOI, then Commit ticked. Reject ticked means the DOI is right as it stands: the row is not listed again. The other classes are information only; Audit never changes a year or an author, so a wrong year is corrected in Edit.
  • Find missing DOIs…: Searches for the DOI of each reference in the subset that has none. Crossref is searched first and is free; OpenAlex is searched only for a reference Crossref has nothing close for, since an OpenAlex search costs 10 of the day's 10,000 credits. For each reference its title, its first author's surname and its year are sent, and nothing else. A reference is not searched for again for 180 days (doi_audit_search_days), found or not, unless its title changes. If the day's OpenAlex credits run low the run stops; start it again the next day and it carries on.
  • Show DOI search results: The searched references by class, each with its candidates: title, first author, year, source, title similarity, and DOI. Exact match: one candidate with the same title and first author and a year within one. Strong match: one candidate whose title is 0.9 or more alike with the same first author. Ambiguous: only a close title, an author that could not be compared, or several candidates. Work without a DOI: OpenAlex has the work but no DOI for it, common for books. Not found: nothing close. A journal DOI is preferred to a preprint's, and of an article and its later reprint the one whose year agrees.
  • Accepting a found DOI: Tick the row and Commit ticked. The box holds the proposed DOI and can be edited; for an ambiguous row it is empty until you type a DOI or press Use this DOI beside a candidate. Reject ticked drops the proposal for good. Nothing is ticked for you.
  • Accept ticked for counts: For a work without a DOI there is nothing to commit, but accepting it tells Fetch citation counts to collect that work's count for the reference. Without an accepted work a reference with no DOI gets no count: a wrong match would give a wrong count with nothing to show it. Rejecting the row withdraws an acceptance.
  • Find published versions…: For arXiv preprints, meaning references with an arXiv identifier (arxivId, eprint, or an arXiv url) and no journal. arXiv is asked, 100 identifiers a request and one request in three seconds, for the DOI the authors gave for the published version; Crossref is then asked for the record of that DOI, or of the reference's own DOI. Only identifiers and DOIs are sent. A preprint asked about in the last 30 days is skipped.
  • Show published versions: The preprints by class. The published version is certain when a DOI is known for it and Crossref's record of that DOI matches the reference by title and first author. Published, same year: the record's year is the reference's. Published, different year: it is not. Possibly published: arXiv gives a journal reference with no DOI, or a DOI Crossref has no record of, or a record that does not match; nothing is proposed. No published version: arXiv knows of none.
  • Fill in ticked (same year): Writes the published version's DOI, type, journal, volume, number and pages onto the preprint's own reference, as one unit: all of the cells listed, or none if any has changed since the table was drawn. The tag, author and year are not touched, and a book keeps its type. It can be reverted like any changeset.
  • Import as a new reference (different year): The preprint's reference is left exactly as it is, so everything that cites its tag still resolves. A new reference is added for the published version, with the library's author and title and the journal's year, venue and DOI, and it opens the same document. The entry can be edited first, and Preview shows what the importer would add; its tag is allocated by the importer, as in Ingest, and its warning that the title duplicates the preprint is expected. Reject drops the proposal for good. This is not a changeset: to undo it, delete the new reference in Edit.
  • Fetch citation counts…: Asks OpenAlex how often each reference with a DOI has been cited. It first shows how many references and requests the run needs and how long it should take, and sends nothing until Start run. Only DOIs are sent, up to 100 in a request. A reference with a result under 30 days old (doi_audit_refresh_days) is skipped, so an interrupted run is resumed by starting it again. Results go to doi-audit/ in the library folder; the references are not changed.
  • Speedy or polite: Speedy sends up to 3 requests at once and is the default for a run of 500 requests or fewer; polite sends one a second. Either can be chosen before starting.
  • Run status: While a run is going the line above the summary shows its progress, refreshed every 5 seconds, with a separate Stop run button; the run ends after the request in flight. One run at a time. A run started from a terminal (archivum doi-audit-run "<query>" --counts -x) shows here too, and archivum doi-audit-status reports the last one. The line also shows the OpenAlex credits left for the day; a run stops itself when few are left, or when a source fails five times in a row.
  • Show citation counts: The subset's counts, most cited first, with the date collected. The table appears by itself when a run ends, unless a review table is open. Every count ever collected is kept in doi-audit/counts.jsonl.
  • Commit ticked: Writes the ticked rows of the page shown, and nothing else. A row whose value changed since the table was drawn is skipped and reported. Nothing is ticked for you.
  • Reject ticked: Records the ticked proposals in doi-audit/decisions.jsonl; they are not proposed again.
  • What Audit can write: Only doi, type, journal, volume, number and pages. It never changes a tag, an author or a year, nor the type of a book. The one other thing it can do is add a new reference for a published version, through the importer.
  • Changesets: Every Commit writes a file to doi-audit/changesets/ in the library folder, with the old and new value of each row. View lists a changeset's rows: tag, field, old value, new value and outcome. Revert puts a changeset's values back, leaving any cell edited since; archivum doi-audit-revert <changeset> -x does the same from a terminal.

Regular Expressions

Most search fields in Archivum support standard regular expressions. Here are common patterns:

Symbol Meaning Example
. Any single character n.t.re matches Nature
^ Start of string ^Smith matches Smith but not Goldsmith
$ End of string 2023$ matches only tags ending in 2023
* Zero or more of previous ba*n matches bn, ban, baan
+ One or more of previous ba+n matches ban, baan, etc.
? Zero or one of previous (optional) cats? matches cat or cats
| Logical OR Nature|Science matches either journal
\d Any digit \d{4} matches a 4-digit year
\w Any word character (alnum + underscore) \w+ matches a whole word
\s Any whitespace (space, tab) Wang\s+R matches "Wang, R" if space exists
[ ] Character class / set [aeiou] matches any vowel
( ) Capturing group (Auto|Machine) groups for priority or repetition
